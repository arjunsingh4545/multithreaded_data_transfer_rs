Disk-aware directory copy.

The crate picks a copy strategy based on the kind of disk on each side: many concurrent copies for SSDs, and a sequential reader → writer pipeline with large buffers when a rotational disk is involved.

§Layers

modulerole
cliterminal input/output only (clap, progress bars)
engineruns a copy: prepare → scan → order → execute
domainpure types and decisions, no I/O
platformOS adapters; the only home of libc and unsafe
utilsmall helpers that know nothing about copying

Each layer depends only on the layers below it.

§Example

use multithreaded_data_transfer_rs::{CopyRequest, Engine, NoProgress};
use tokio_util::sync::CancellationToken;

let engine = Engine::new();
let prepared = engine.prepare(&CopyRequest::new("/mnt/a", "/mnt/b"), &NoProgress)?;
println!("{}", prepared.plan());
let summary = engine.execute(&prepared, &NoProgress, &CancellationToken::new())?;
println!("copied {} files", summary.stats.files);

Pure types and decisions. Nothing in this layer performs I/O, so every rule here can be unit-tested with plain values.
engine
Running a copy: Engine::prepare decides, Engine::execute copies.
error
Crate-level error type, assembled from each layer’s own error enum.

OS adapters. Each trait lives next to its implementations; this is the only layer allowed to call libc or use unsafe.

Small helpers shared by every layer. Nothing here knows about copy plans or disks.
